#交互定义依据
1Guest 模式定位:未登录用户打开 App 默认着陆 Feeds 页,可免登录浏览全部帖子、搜索、看帖子详情、看 Discover / Places / Events —— 只拦「动作」,不拦「浏览」#3 注册与登录 · #1 新手引导 降低冷启动门槛
2Guest 权限矩阵:可 → 浏览 / 搜索 / 看详情;受限 → Follow · Like · Comment · Share · Chat · Bookmark · Create Event · My Hub。点任意受限动作统一弹登录墙 bottom sheet#3 统一拦截模式
3登录墙规则:弹层保留动作上下文(pending action: creator id),主按钮「Create free account」直达注册 Step 1,次按钮「I already have an account」,ghost「Not now — keep browsing」可返回继续逛X / IG / TikTok deferred action 模式
4Follow → 完整标准注册流:Create account → Step 1 建户(Phone/Email + 三方登录)→ Step 2 验证码 → Step 3 完善信息/稍后补充双分支 —— 与 Sign Up 系列设计稿完全同一条链路,不另造游客专用流程#3 单一流,两处入口
5回跳续作:注册链路全程顶部显示 pending 上下文条;完成后自动回跳 Feeds 原位置并完成 Follow,按钮变 Following ✓ + 欢迎 Toast;推荐页(稍后补充分支)只展示、不打断回跳#3 · #1 意图零丢失
6Guest 身份可视化:顶栏常驻 Guest chip + Sign in;引导横幅可关闭、注册成功后消失;底栏受限 Tab(Chats / My Hub)带金色锁标;游客态无未读徽章(无可读通知源)#5 通知中心 · #12 P002 底栏规范延续
7数据衔接:游客期浏览/搜索本地缓存,注册后并入账号画像驱动推荐(衔接 Step 3 推荐页与 #7/8 推荐系统);清 App 数据 = 游客数据丢失,不提示注册也合规(仅本地)#7/8 推荐 隐私友好
